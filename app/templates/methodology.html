1. Zero-SSRF Architectural Immunity

Passive string analysis without remote network execution

SSRF Safe

A fatal vulnerability in conventional security scanners is Server-Side Request Forgery (SSRF) and untrusted web scraping. When an automated engine visits a submitted URL, it exposes internal microservices (e.g. AWS/GCP metadata endpoints at 169.254.169.254, internal Kubernetes APIs, or private subnets) to blind discovery and remote exploitation.

URLShield never visits, renders, or establishes TCP connections to audited URLs. Analysis is conducted purely through passive lexical decomposition, Shannon entropy measurement, structural grammar extraction, and machine learning inference. This guarantees immunity to SSRF, drive-by exploits, browser zero-days, and canary token triggers.

3. Dataset Provenance & Leakage Prevention

Academic research standards for legitimate and phishing samples

To eliminate data fabrication and synthetic bias, URLShield trains exclusively on validated public datasets:

  • Legitimate Baseline: Research-backed Tranco Top Sites (NDSS 2019, CC-BY 4.0 license).
  • Active Phishing: PhishTank Verified Feed (data.phishtank.com) and OpenPhish Community Feed.
  • Malware Distribution: abuse.ch URLhaus (CC0 Public Domain).

Group-Aware Partitioning: In naive random splits, URLs from the same domain (e.g., different paths on malicious-site.com) leak into both train and test sets, causing grossly inflated accuracy. URLShield strictly groups training and validation sets by registered domain (GroupKFold), ensuring the test set contains 100% unseen domain infrastructure.

4. Privacy & Sensitive Query Redaction

Protection against credential and session leakage in audit logs

Submitted URLs often contain authentication tokens, session IDs, or password reset parameters in query strings (e.g., ?token=secret123&pass=secret). Before URLShield persists any scan into SQLite or outputs to logs, sensitive query parameters matching security keys are automatically stripped and replaced with [REDACTED].
